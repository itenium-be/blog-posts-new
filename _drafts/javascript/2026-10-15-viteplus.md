# Vite+: Simplifying the Web Development Toolchain

Setting up a modern web project usually involves connecting a long list of independent tools. A standard baseline requires ESLint for static analysis, Prettier for formatting, Vitest for testing, and Husky for repository hooks. Combined with environment managers like NVM and package managers like pnpm, this sprawl creates heavy configuration overhead before any real code is written.

Vite+ (V+) simplifies this process by pulling the core development lifecycle into one interface, handling linting, formatting, testing, and dependency management. It packages standard development practices into a single toolchain that is faster and easier to maintain.

## Configuration and Tooling
Vite+ mostly cuts down on configuration files. It replaces isolated files like `.eslintrc`, `.prettierrc`, and `vitest.config.ts` with a single `v.config` file. This central file controls formatting, static analysis, git hooks, and testing. It also includes project templates for React, Next.js, and Astro, applying the standard conventions for each framework so teams spend less time setting up new repositories.

Under the hood, Vite+ replaces older JavaScript tools with Rust-based alternatives. OxLint and OxFormat replace ESLint and Prettier; they share the same rules and behaviour but run much faster, speeding up both local development and CI pipelines. It also runs TypeScript checks during the linting phase, removing the need for separate `tsc` commands and enforcing type safety with less overhead.

## Standardising Environments
Getting a whole team on the same Node.js version and package manager is often difficult, but Vite+ handles this natively. Developers use `vp install`, `vp run`, and `vp outdated` as standard commands, whether the project underneath uses npm, pnpm, or bun.

It also removes the need for external tools like NVM. Running `vp env pin 22` locks the Node.js and package manager versions for the project and automatically updates the `engines` field in `package.json`.

## Quality Assurance and CI/CD
Strict quality checks matter more now that teams use AI coding assistants, as generated code often introduces subtle formatting or type errors. Vite+ enforces these standards automatically. By default, it runs `vp check --fix` on staged files to correct formatting and linting errors before a commit. Teams can also configure the tool to block commits entirely if it finds errors.

For larger codebases, Vite+ includes monorepo support. It reads standard workspace structures, such as `apps/` and `packages/` folders, and routes commands to specific modules while sharing configuration across the repository.

Because testing, linting, and formatting run through one tool, a complete CI pipeline needs very little configuration in its YAML file. Testing runs through Vest, a custom wrapper for Vitest, and the `vp test` command includes native coverage reporting and watch mode. A VS Code extension provides OxLint analysis and on-save formatting directly in the editor.

## Migration
Moving an existing project to a new toolchain always carries risk. Vite+ includes a `vp migrate` tool to automate the move from ESLint and Prettier. It moves the configuration to the Ox tools, updates VS Code settings, and adds pre-commit hooks. This works well for standard setups, but older projects with custom ESLint plugins will still need manual fixes after migration.

## Next Steps
If you want to evaluate the toolchain without risking an existing codebase, the easiest approach is to scaffold a new project. You can install the CLI globally and run `vp create vit` in your terminal to set up a configured baseline environment. Full installation instructions and framework-specific guides are available in the official documentation.
